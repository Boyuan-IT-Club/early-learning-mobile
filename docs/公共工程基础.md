# 公共工程基础（第一批）

本文件记录可在各业务模块设计完成前确定的工程约定。依据冻结技术方案的数据关系、离线本地存储及事务要求，沿用仓库 React 和现有 Capacitor/SQLite 依赖，不改变业务表或五份 JSON 的结构。
## 0. 快速启动
启用本地开发页面：
npm install
npm run dev

验证 Android：
npm run build
npx cap sync android
npx cap open android


## 1. 本批交付与边界

| 项目 | 已落实 |
|---|---|
| 检查基线 | TypeScript strict，统一 typecheck / lint / test / build / check，清理已删除模板资源引用 |
| 公共约定 | 目录职责、本地 ID、日期、稳定错误码、冻结状态类型、现有 JSON 边界校验 |
| 数据库 | 唯一生产组装点、Android 驱动、顺序迁移、外键检查、串行访问、事务上下文复用 |
| 应用启动 | Android 等待初始化；失败显示错误；浏览器明确显示预览环境 |

业务状态推进、统计、各模块公开接口、HTTP/Token 协议、文件与媒体适配、备份恢复、CI 不属于本批实现。对应模块仍需完成自己的设计和验收。

## 2. 目录与依赖

| 目录 | 责任与依赖约定 |
|---|---|
| `src/app` | 应用启动、页面入口、依赖组装；唯一生产数据库实例在 `database.ts` 创建 |
| `src/modules/<模块>` | 私有仓储、业务用例、状态转换和 UI；公开入口为本模块 `index.ts` |
| `src/infrastructure` | 平台能力适配；不依赖 app 或业务模块 |
| `src/shared/contracts` | 纯公共类型和校验；不持有数据库、全局业务状态或 React 组件 |
| `src/shared/ui` | 公共 UI；不直接访问数据库或持有模块业务规则，组件需要时再添加 |

模块仓储通过参数接收 `DatabaseReader` / `DatabaseTransaction`，不另建连接。业务用例通过组装注入的 `Database` 开启事务。UI 调用用例，不直接执行 SQL；模块之间通过公开入口协作，不跨目录调用私有实现或自行写对方表。

公共入口统一从 `shared/contracts` 导入。纯 TypeScript 文件内部可用 `.ts` 扩展名，便于 Node 内置测试直接执行；现有 bundler 配置支持这种写法。不要重复定义相同的 JSON、状态或 Code 类型。

## 3. 公共值与错误

- `LocalId<'表名'>` 表示 SQLite 安全正整数主键，经 `parseLocalId` 校验；不与云端 ID、稳定 Code 混用。JSON 中的 Code 沿用现有类型。
- `DateOnly` 经 `parseDateOnly` 校验 `YYYY-MM-DD` 和日历有效性，出生日期不经时区换算。
- 新时间戳经 `toIsoDateTime` 转为 UTC ISO 8601，与 SQLite 默认值一致。更新时由业务层显式写 `updated_at`。
- `AppError` 用稳定 `code` 供程序分支判断，`message` 只包含适合展示的信息。`ContractError` 保留原类名和字段路径，同时使用 `INVALID_JSON_CONTRACT` 错误码。
- 不把 SQL、绑定值、Token、儿童原话或底层异常直接作为日志/用户错误。业务层只捕获自己能处理的错误；未知异常向上交给应用入口处理。
- `states.ts` 仅定义冻结状态值，不替模块决定允许的状态转换。类型不是运行时校验：仓储需把查询结果的 `unknown` 字段按契约校验，JSON 使用现有解析器。

## 4. 数据库接入

`app/database.ts` 使用已安装的 `@capacitor-community/sqlite` 创建 `early_learning` 数据库。应用只持有一个 `Database`；生产入口仅允许 Android。测试使用 Node SQLite 驱动，浏览器不提供伪业务数据库。

公开操作：

| 操作 | 语义 |
|---|---|
| `initialize()` | 幂等打开、迁移和完整性检查；并发调用排队 |
| `read(reader => ...)` | 一组读取独占访问队列，不读到另一个用例的未提交中间结果 |
| `transaction(tx => ...)` | 开启一次本地事务，回调内所有仓储共用同一 tx，成功提交、异常回滚 |
| `close()` | 等待已排队任务结束后关闭连接；后续操作可重新打开 |

`DatabaseReader.query` 返回 `Record<string, unknown>[]`。`DatabaseTransaction` 额外提供 `run`，返回受影响行数和可选插入 ID。仅 INSERT 可使用 `lastInsertId`，UPDATE/DELETE 不能据此确定记录。

仓储只使用单条参数化 SELECT / INSERT / UPDATE / DELETE，不自行执行 DDL、PRAGMA 或事务命令；当前接口不支持 CTE 和多语句 SQL。值用 `?` 绑定，只接收字符串、有限数值和 null。语句正文不得含分号，末尾单个分号除外；文本中含分号时通过参数传入。

### 共享事务示例

下面只展示文档已确定的“两个刷新凭证一起保存”操作，未定义或调用后端刷新协议：

```ts
import type { Database, DatabaseTransaction } from '../infrastructure/database';
import type { LocalId } from '../shared/contracts';

async function saveTokens(
  tx: DatabaseTransaction,
  accountId: LocalId<'user_local_account'>,
  accessToken: string,
  refreshToken: string,
) {
  return tx.run(
    'UPDATE user_local_account SET access_token = ?, refresh_token = ? WHERE id = ?',
    [accessToken, refreshToken, accountId],
  );
}

// database 由 app 注入；网络请求结束、响应已校验后，再进入短事务。
async function persistTokens(
  database: Database,
  accountId: LocalId<'user_local_account'>,
  accessToken: string,
  refreshToken: string,
) {
  return database.transaction(async tx => {
    await saveTokens(tx, accountId, accessToken, refreshToken);
    // 如用例需要其他仓储操作，也把这个 tx 传入，异常时一起回滚。
  });
}
```

事务回调及其调用链**不得再次调用根 Database 的 read/transaction/initialize/close**，否则新的任务会排在当前任务后而互相等待。内部复用传入的 tx，不嵌套开启事务。上下文不暴露提交/回滚能力，离开回调后不可保存再用。

所有 SQL 都应 await；入口也会等待已经排入上下文的操作完成，并在任一 SQL 失败后回滚整笔事务，即使调用方捕获了 SQL 错误。不要在事务内等待网络、AI、录音、压缩或用户操作。不要依赖延迟回调在事务结束后写库。

提交响应丢失可能意味着数据已经提交。此时返回 `DATABASE_COMMIT_FAILED` 并停止使用连接，不自动重放；关闭并重开后，由业务用例根据已保存结果判断下一步。完成课堂等业务仍须自行实现幂等与完成校验，公共事务不能替代它们。

React StrictMode 的 effect 清理不关闭全局数据库，避免卸载/重挂载与初始化互相影响。后台切换也不自动关闭；完整恢复或生命周期结束需要关闭时，必须由 app 协调停止新用例后调用。

## 5. 迁移与已有数据

- 每次打开连接，在事务外启用并核对外键，执行 `quick_check` 和外键关联检查。
- `PRAGMA user_version` 是本地迁移版本，与 JSON `schema_version`、评分 `rubric_version`、内容 `content_version` 无关。
- 初始迁移版本为 1，直接复用既有 `001_initial_sqlite.sql` 的 18 张表。接入器只移除已知的外层 PRAGMA/BEGIN/COMMIT，由迁移器统一控制事务；原 SQL 文件保持可单独执行。
- 新迁移按 2、3……连续追加，不修改已执行的旧迁移。迁移 SQL 不带事务控制或 PRAGMA；迁移内容、外键校验和版本写入处于同一事务。
- 不注册插件自动升级，避免同时存在两个版本/事务管理入口。SQLite 驱动的 `execute` 和 `run` 显式关闭插件隐式事务。
- 版本为 0 且已有用户对象的旧开发库返回 `UNVERSIONED_DATABASE`，保留原数据。不能仅重跑 IF NOT EXISTS 或直接标记版本 1；需先核对真实结构和数据，再另行实施经过验证的迁移。
- 高于应用支持版本的库拒绝打开，不自动降级；坏库和迁移失败也不通过删库恢复。
- 本批完整性检查仅涉及 SQLite 结构和外键，不代表附件存在性、JSON 语义或全部业务不变量已经校验；这些由对应边界和用例负责。
