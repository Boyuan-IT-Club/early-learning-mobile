|**本地SQLite\.case\_progress\_stats: 个案康复数据统计**|||
|---|---|---|
|字段名|类型|含义|
|case\_id|INTEGER|PK \+ FK 引用 case\_info\.id|
|lesson\_count|INTEGER|累计课次|
|answer\_num|INTEGER|回答问题总数|
|before\_hint\_score\_sum|INTEGER|提示前总分|
|final\_score\_sum|INTEGER|最终总分|

前端展示累计课次、课程历史、提示前均分和最终均分。提示前均分 = before\_hint\_score\_sum / answer\_num；最终均分 = final\_score\_sum / answer\_num。

只统计 COMPLETED 课堂中的有效 ANSWERED 问题，0分计入分母，SKIPPED 排除；两项共用 answer\_num，分母为0显示“暂无数据”。未提示时最终分沿用提示前分，使用提示时取提示后分，不取两次最大值。第五题“自己相似经历补充描述”同样由 AI 按0/1/2分评分并计入。前测/复评不计入课堂康复统计。

课堂确认完成、进度推进、两类统计更新及由本次完成触发的计划完成状态更新，应在同一本地事务中提交；重复确认不得重复累计。仅未完成课堂允许作废，COMPLETED 课堂不可作废，不提供完成课堂的统计撤销流程。统计缓存可从有效 COMPLETED 课堂重建；未完成课堂作废不产生统计贡献，其进度按计划状态与成员参与条件处理，并清空恢复位置。

具体数据不需要存在这里，可以存在课程里

case\_progress\_stats 是一张缓存表

|official\_course\_code|VARCHAR|官方课程稳定编号；同一门课程不同版本保持一致，用于云端与本地课程同步匹配，私人课程为空|

|status|VARCHAR|ACTIVE / DISABLED / DELETED|
|created\_at|TIMESTAMP|创建时间|
|updated\_at|TIMESTAMP|最后更新时间|

UNIQUE\(official\_course\_code, content\_version\)

官方课程下载的时候按照official\_course\_code比对并新增一行，老课程设为DISABLED

`DISABLED` 表示不可再用于新建计划/新选择课程，不影响已经通过 `plan_course` 引用该版本的既有计划继续执行，也不影响历史数据查看。

私人课程被 plan\_course 引用后，其内容不可原地修改；修改时复制为新的 course 记录（新的本地 id、source=PRIVATE、official\_course\_code为空），原计划和历史继续引用原课程。未引用的私人课程可编辑。被引用的官方课程版本和评估材料同样保持内容不变，修订通过新版本发布。

创建课程时从 `question_bank` 多选题型并填写 `activity_configs_json`。source=OFFICIAL 时 official\_course\_code、content\_version 必填，二者联合唯一。被 `plan_course` 或 `course_instance` 使用的课程不可物理删除，只能设为 `DISABLED`。

|scale\_scores\_json|TEXT|十题评价分数；未填写时为 \{ "schema\_version": 1, "scores": \[\] \}|
|started\_at|TEXT|本次课堂开始时间|
|completed\_at|TEXT|教师确认完成时间|
|void\_reason|TEXT|作废原因|

课堂完成条件根据课程实际选择的题型校验：图片排序必须提交儿童实际顺序；问题问答必须处理全部问题，ANSWERED 的提示前回答须完成内容确认和有效 AI 评分，已提示时提示后回答也须完成确认和有效 AI 评分；SKIPPED 不进入统计，评分缺失或失败不得当作0分；故事叙述必须有确认录音、AI 评分成功和十题评价恰好 10 个有效分数。教师确认后将 `course``_instance.status` 置为 `COMPLETED`，并推进对应 `course_case_progress`；作废课堂不推进进度。

课堂的 `activity_results_json` 与课程的 `activity_configs_json` 对应。图片排序保存 `child_order`；问题问答保存每题的回答结果；若选择故事叙述，录音、转写和 AI 结果使用本表已有的 `audio_file_id`、`transcript_text`、`ai_score_json` 字段。

## 顶层协议

- ActivityConfig、ActivityResult、AIScore 使用 schema\_version=2；ScaleScores、ResumeState 使用 schema\_version=1。schema\_version 表示数据结构版本，rubric\_version 表示评分标准版本，content\_version 表示课程或材料内容版本，三者独立。

- 空结果初始化为 \{"schema\_version":2,"rubric\_version":null,"activity\_results":\[\]\}。服务端在本次首次评分前确定 rubric\_version，客户端持久保存；本次后续问答、提示后评分、叙事评分和重试均沿用该版本。

- 旧布尔结果不能机械转换为0/1/2分，不能只修改版本号冒充新版结果。课程不再填写逐题评分规则。

- 同一课程或材料中，每种活动类型最多出现一次；activity\_id 唯一，question\_id 在对应问答活动内唯一，content\_item\_id 在对应叙事活动内唯一。现有主表只保存一份故事录音、转写及叙事评分。

- 问答评分只保存在回答对象内，不重复放到 ai\_score\_json。模型标识、提示词版本、评分标准版本由服务端记录，不依赖模型自报。

- 回答或评分依据修改后使对应旧评分失效；服务层校验请求对应的输入修订，拒绝迟到的旧结果覆盖新内容。

## 评分调用与校验

客户端提交本次确认的回答/叙事文本和课程或材料的相关配置。私人课程不假设云端已有内容。模型需要识别图片时，必须取得所引用图片的实际内容，不能只传 file\_code；若采用纯文本评分，需要经过确认的图片内容说明，不能让模型凭空猜图。

云端组合统一评分配置、故事依据、具体问题和本次回答后调用模型，验证返回项目、分数范围和证据，再由客户端写入相应结果。课程文本、儿童回答均作为待评价材料，不作为系统指令。评分所需儿童材料仅在云端调用期间处理，业务数据仍保存在本地。

## 报告结构

报告由宏观结构、微观结构、问题推理三个部分组成，每部分一张雷达图；图旁按相同顺序逐项显示条目名称、得分和完整 AI reason。不得将 reason 摘要化、截断或只展示 summary；排版应自动换行，篇幅较长时可跨页续排，保留条目对应关系。

|雷达图|维度来源|本例维度数量|分数及理由来源|
|---|---|---|---|
|宏观结构|事件顺序、情节结构、主题体现、故事连贯性、因果逻辑、五组图片叙事内容、细节拓展|11|ai\_score\_json\.macrostructure\.dimensions 与 content\_items 中各项的 score、reason|
|微观结构|叙事产生性、词汇丰富度、心理状态词、句法复杂度、指称衔接、连词衔接|6|ai\_score\_json\.microstructure\.productivity 与 dimensions 中各项的 score、reason|
|问题推理|课程或评估材料配置中的每一道具体问题，按 questions 顺序|5|activity\_results\_json 中对应问题的最终 ai\_score\.score 和 reason|

每个评分条目对应一个维度，所有雷达图统一使用0—2分刻度，显示0、1、2刻度值，不转百分制，不合并条目或计算维度均分。宏观结构的图2/3、图4/5分别是一个评分条目，不能拆成逐张图片轴。叙事产生性的四项量化统计不单独作为轴，其 AI 0/1/2分才是该维度的值。

宏观和微观按上述原表顺序展示；图片分组按课程配置 content\_items 的顺序插入，维度名称由评分配置和课程图片分组取得，不能显示 content\_001 等内部代码。问题推理图每条轴标题可使用题号，图旁展示完整题目、最终得分及完整对应理由。其他课程的问题数和图片分组数以实际配置为准，不写死为本例数量。

问题推理使用最终评分：hint\_used=true 时读取 after\_hint\.ai\_score，否则读取 before\_hint\.ai\_score；理由与所选分数必须来自同一次评分，不混用提示前后结果，不取最高分。第五题“自己相似经历补充描述”同样作为一条轴，最高2分并计入问答均分。

正式报告在本次评估或课堂确认完成且所需评分齐全后生成。SKIPPED 标记为“跳过/未评分”，不赋0分、不编造 reason；缺失点不连成代表实际得分的完整多边形。活动未选择时，在对应报告位置说明“未进行该活动”，不生成虚构评分。少于三个有效评分维度时保留该部分和逐项完整理由，以分数列表展示，避免绘制无意义的雷达多边形。标准七图五问材料按上述三张雷达图呈现。

报告是已有配置和结果的展示产物，无需新增报告评分 JSON 或数据表，生成的PDF继续通过主表 report\_file\_id（已有该字段时）引用；课堂报告如后续要求持久保存入口，再单独明确其关联位置。
